# Open HTML to Figma — Agent Handoff

## Product goal

Build a Figma desktop plugin that accepts a local, well-formed HTML document generated by an AI or designer and produces a Figma frame that closely matches the page rendered at a selected desktop viewport.

The output must be useful after import:

- Preserve the visual hierarchy, dimensions, positions, typography, colors, borders, gradients, shadows, images, and SVGs as closely as Figma allows.
- Keep normal layout and text editable as Figma layers instead of flattening the whole page into one screenshot.
- Allow the imported root to be created either as a Frame or a Component.
- Make failures and progress obvious to the person using the plugin.

## Core approach

The plugin does **not** reimplement CSS layout. The browser is the layout engine:

1. The UI accepts pasted HTML or an `.html` / `.htm` file.
2. It renders the document in an isolated iframe at the chosen viewport width.
3. It waits for fonts and images, then records the visible DOM's computed layout and styles.
4. It sends a serializable tree plus raster image bytes to the Figma main thread.
5. The main thread creates nested Frames, Text nodes, and image Rectangles using parent-relative coordinates.

The current output intentionally uses absolute positioning. Do not add Auto Layout merely because the source uses flex or grid; first preserve browser parity. Auto Layout may be inferred later for simple containers only.

## Repository map

| File | Responsibility |
| --- | --- |
| `ui.html` | Plugin UI, file validation, loading state, isolated browser render, DOM serialization, asset rasterization |
| `code.ts` | Figma main thread; turns the serialized tree into Figma nodes |
| `code.js` | Build output from `code.ts`; regenerate with `npm run build` |
| `manifest.json` | Figma plugin entry points and network permissions |
| `examples/` | Sample documents used for manual visual regression testing |

## Non-negotiable UX behavior

- If there is no pasted HTML when the user clicks import, show a clear error and open the file picker.
- Reject non-HTML files even when a user bypasses the file-input filter.
- During conversion, disable the import button, show an animated spinner, and communicate the current phase.
- If the Figma main thread does not respond, end the loading state with a useful timeout error rather than leaving the UI stuck.
- On success, select and zoom to the imported root node.

## Fidelity priorities

Prioritize in this order:

1. Correct isolated rendering and desktop viewport measurements.
2. Typography, including installed fonts, line height, spacing, wrapping, and inline styled text.
3. Backgrounds, images, SVGs, borders, corner radii, and shadows.
4. Browser-only effects that cannot be represented as editable Figma layers should use a clearly named raster fallback rather than silently disappearing.
5. Editability: avoid unnecessary structural Frames; keep text and simple vectors editable.

## Current limitations to improve

- CSS color parsing supports only hex and `rgb()` / `rgba()`.
- Only simple linear gradients are rebuilt; layered, radial, and conic backgrounds need a raster fallback.
- Inline SVGs are currently rasterized; use native Figma SVG nodes when feasible.
- Rich text runs inside elements such as `<p><strong>…</strong></p>` are not preserved as mixed Figma text styles.
- Browser and Figma font metrics can differ. Page fonts must be available in Figma for closest results.
- Relative and cross-origin images may fail because local file paths and CORS cannot be reliably read by the plugin.
- CSS filters, transforms, masks, blend modes, animations, and complicated clipping cannot always become editable Figma layers.

## Implementation principles

- Keep source-page styles isolated from the plugin UI. Do not inject source `<style>` tags into the plugin document.
- Keep the browser-measured geometry as the source of truth.
- Prefer exact visual output plus a localized raster fallback over a misleading editable approximation.
- Never leave the UI in a loading state after an error or timeout.
- Build after TypeScript changes: `npm run build`.
- Test manually in Figma desktop with both `examples/sample.html` and `examples/neuroessence.html`.

## Suggested next improvements

1. Add a screenshot/raster fallback for unsupported backgrounds and effects.
2. Use `figma.createNodeFromSvg()` for inline SVG where possible.
3. Preserve mixed text ranges using Figma range styling APIs.
4. Add golden regression tests for serialized layouts and key visual properties.
5. Infer Auto Layout only for simple, high-confidence flex containers.
